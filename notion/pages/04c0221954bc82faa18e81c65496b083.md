## 2. 통합·별개 유지 확정

### 분실물 필터 11-18·11-23

- 사용자 확정 (2026-10-15): 11-18 선택 이벤트를 11-23 적용 이벤트 하나로 통합한다. 11-18.분실물_게시물종류_클릭 (11-23 통합) (원문 ID: 0b10221954bc83dea9960100951f760d)는 통합 이력으로 보존하고 별도 전송하지 않는다.
- 현행 명세: 11-23. 분실물_필터_적용_클릭 (원문 ID: 37b0221954bc8395897801f58e65d2a6). event\_name은 DA2, screen\_view는 lost\_item\_list, label은 <code>board__lost_item_list__filter__apply</code>, category는 click이다. 적용하기 클릭 순간 최종 상태를 보낸다.
- 최종 값은 filter\_scope(목록), filter\_post\_type(물품 카테고리), filter\_item\_type(물품 종류), filter\_status(물품 상태) 네 개의 별도 STRING 파라미터로 구분한다. 하나의 JSON·혼합 리스트 문자열에 넣지 않는다. 기존 value ‘분실물’은 공통 식별값으로 유지한다.
- 매 적용마다 네 키를 모두 보내고 기본·전체 상태는 ‘전체’로 쓴다. 단일 선택은 한국어 값 하나, UI가 허용하는 복수 선택은 중복 제거 후 정의된 순서로 ‘\|’ 연결한다. 예: filter\_item\_type=‘카드\|지갑’. 전체와 개별 값을 함께 기록하지 않는다.
- 11-22 필터 열기는 유지한다. 선택 도중이나 적용하지 않고 닫을 때 적용 로그를 보내지 않는다. 적용 횟수는 이벤트당 1회로 계산하고 항목을 펼친 행 수로 세지 않는다.
- 이력 비교: 기존 선택 이벤트와 적용 이벤트는 집계 단위가 다르다. 구현·배포 전환일과 이전→신규 대응을 기록한다.
- 개발 후속: 신규 네 파라미터의 SDK 전송·dbt 추출·마트 열 반영이 필요하다. 명세 변경만으로 기존 event\_value에 자동 반영되는 값이 아니다. 개발 반영 후 수집·중복 검수는 사용자 요청대로 후속 작업이다. 상세 값·기본값 규칙은 11-23을 따른다.
