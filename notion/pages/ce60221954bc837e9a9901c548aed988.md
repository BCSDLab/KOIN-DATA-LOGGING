- 이미 확정한 요청과 적용 범위를 다음 작업의 기본값으로 이어간다. DA1 사례와 현재 DA2 범위를 구분하고, 기존 사용자 수정·보류 상태를 오래된 백업으로 덮어쓰지 않는다.

### 커서와 클릭 표시 제거 — 이번 작업에서 성공

1. 화면 이동을 끝낸 후 휴대폰과 연결의 메인 창에서 앱 창 바깥에 위치한 중립적인 제목 표시줄을 클릭한다.
2. 커서를 움직이지 않고 KOIN 앱 창을 다시 앞으로 가져온다.
3. 새로 캡처한 이미지에 커서와 파란 강조 표시가 없는지 확인한다.

최대화한 앱 창에서는 PC 여백에 커서를 두고 휴대폰 화면 영역에 포함되지 않도록 했다. 과거 작업의 좌표를 그대로 재사용하지 않는다. 창 위치와 크기, 캡처 영역을 매번 확인한다.

근거: 로컬 콜밴팟 이미지의 실제 메타데이터와 <code>capture-quality-processing.json</code>. 프롬프트에서 1080 × 2340을 요청했지만 실제 출력은 853 × 1844였다. 요청한 크기와 저장된 크기를 구분한다.

다음 작업에서는 가능한 한 큰 창이나 직접 얻을 수 있는 원본 캡처를 먼저 사용한다. 확장자나 문서 표시 크기만 바꾸는 것으로 화질이 개선됐다고 판단하지 않는다. 파일 형식을 확인하고 그 형식에 맞는 확장자와 업로드 MIME을 사용한다.

업스케일링을 사용할 때는 다음을 대조한다.

- 한글 문구, 날짜·시각·인원 등 숫자.
- 버튼·아이콘과 배치, 색상, 선택·비활성 상태.
- 팝업 높이와 배경의 가림 상태, 원래 화면 구성.
- 커서, 클릭 표시, PC 제목 표시줄·불필요한 여백의 포함 여부.

ImageGen 결과는 새로 생성된 비트맵이므로 무가공 원본이라고 표시하지 않는다. <code>선명도 개선본</code>이라고 짧게 표시하고 원본을 보관한다. 원본에서 읽을 수 없는 문구를 추정해 새 글자로 채우지 않는다.

프롬프트에 담을 최소 조건:

```txt
입력은 실제 앱 캡처다. 새 UI를 디자인하지 않는다.
휴대폰 화면 바깥의 PC 여백만 제거하고 화면 비율을 유지한다.
모든 문구·숫자·아이콘·색상·배치·선택 상태를 원본대로 유지한다.
커서·클릭 강조·워터마크·기기 프레임·새 항목을 추가하지 않는다.
출력 파일의 실제 크기를 확인하고 원본과 대조한다.
```
</details>

위 선명도 개선은 당시 사용자가 허용한 사례다. 현재 로깅의 빨간 박스 표시는 원본 복사본에 코드로 테두리만 추가하는 합의가 우선이다. 공통 이미지 작업 규칙은 [로깅 통합 가이드](3c30221954bc8214b1c481c5bbb6fba5.md)를 따른다.

<details>
<summary>분실물 빨간 박스 작업 기록 — 2026-10-12</summary>

1. 원본과 항목 매핑을 저장한다. 같은 파일이라도 어떤 서비스·화면·로그·플랫폼의 근거인지 구분한다.
2. 현재 화면과 추가 이미지에서 해당 버튼이 실제로 보이는 상태를 선택한다. 타인 게시물에서 본인 전용 수정·삭제 버튼의 위치를 추정해 표시하지 않는다.
3. 코드로 원본 PNG의 복사본에 빨간 테두리를 그린다. 원본 파일을 직접 덮어쓰지 않는다.
4. 좌표는 해당 파일의 실제 크기를 기준으로 잡는다. 확대·축소된 미리보기 좌표를 원본 픽셀 좌표로 그대로 사용하지 않는다.
5. 표시본의 버튼·문구·상태를 눈으로 확인한다. 해상도와 빨간 테두리 밖 픽셀도 원본과 대조한다.
6. 같은 캡처를 여러 로깅에 사용할 때는 기능별로 다른 박스를 표시한다. 공유 이미지가 필요한 경우 사본 파일을 업로드한다.
7. 웹·Android 사진을 실제 플랫폼 범위에 맞춰 배치하고, 오래된 사진·공통 UI·Figma 근거를 표시한다.
8. 저장된 노션을 다시 읽어 사진이 해당 로깅 토글 안에 있고 원본 이미지가 유지되는지 확인한다.

이번 사례에서는 새 표시본 47개를 만들었다. 분실물·습득물 수정의 공통 이미지 두 쌍을 제외하면 고유 표시 파일은 45개였다. 기존 빨간 박스 캡처도 사본으로 업로드해 총 60개 이미지 블록을 새 로깅에 배치했다. 원본 로깅에 있던 이미지 95개는 유지했다.
</details>

```txt

category·value·트리거 유지 또는 변경:
시도한 방법과 실제 결과: 성공 / 실패 / 미확인
```
