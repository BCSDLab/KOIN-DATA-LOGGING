## 1. event\_name — 로깅 담당자 코드(DA1, DA2 …)

### 의미

- event\_name은 <b>그 로깅 명세를 작성한 DA 담당자</b>를 나타낸다.
- 과거에는 CAMPUS, BUSINESS, USER처럼 <b>팀 이름</b>을 썼다. 팀이 통합되면서 담당자 코드로 바꾼다.
- 서비스나 도메인을 뜻하지 않는다. 어느 서비스의 이벤트인지는 <code>service_name</code>과 event\_label의 첫 단어로 구분한다.

### 코드 목록

| 코드 | 담당자 | 상태 |
| --- | --- | --- |
| DA1 | 이상민 | 사용 중 |
| DA2 | 김창윤 | 사용 중 |

### 부여 규칙

1. DA에 인원이 늘면 다음 번호(DA3, DA4 …)를 새로 부여한다. 서비스·도메인마다 번호를 늘리지 않는다.
2. 한 번 부여한 코드는 다른 사람에게 다시 쓰지 않는다. 담당자가 활동을 마쳐도 코드는 "종료"로 남긴다.
3. 담당자가 바뀌어도 <b>이미 수집 중인 이벤트의 event\_name은 바꾸지 않는다.</b> 바꾸면 같은 이벤트가 두 이름으로 나뉘어 과거 데이터와 이어지지 않는다.
4. 새로 만드는 이벤트에만 작성한 담당자의 코드를 쓴다.

### 과거 팀 이름과의 대응

| 과거 event\_name | 의미 |
| --- | --- |
| CAMPUS | 캠퍼스 팀 |
| BUSINESS | 비즈니스팀 |
| USER | 유저(계정) 팀 |

## 2. event\_category — 행동 종류

### 원칙

- event\_category에는 <b>사용자가 실제로 한 행동</b>만 넣는다. 나가는 방법, 화면 이름, 버튼 이름 같은 값은 넣지 않는다(이런 값은 value에 넣는다).
- 아래 목록에 있는 값만 쓴다. 새 값이 필요하면 이 표에 먼저 추가한 뒤 쓴다.
- event\_label 끝에 행동을 붙인 경우(같은 기능에 행동이 여러 개일 때), 그 값과 event\_category를 같게 맞춘다.

### 목록

| event\_category | 뜻 | 언제 쓰나 | 예시 event\_label |
| --- | --- | --- | --- |
| click | 버튼·메뉴·탭·항목을 누름 | 대부분의 버튼·탭 클릭. 화면을 나가는 버튼(뒤로가기·이탈)도 포함 | <code>shop__shop_list__shop</code>, <code>cafeteria__dining__soldout__photo</code> |
| select | 여러 선택지 중 하나를 고름 | 코너처럼 정해진 보기 중 하나를 고르는 행동 | <code>cafeteria__dining__soldout__select</code> |
| scroll | 목록·화면을 스크롤함 | 스크롤 동작 1번(손을 떼거나 멈출 때)마다 1회 | <code>shop__shop_list__list</code> |
| swipe | 화면을 손가락으로 밀어 넘김 | 스와이프 제스처로 화면을 나갈 때 | <code>shop__shop_detail__back</code> |
| submit | 입력한 내용을 제출하는 버튼을 누름 | 제보처럼 양식을 최종 제출하는 버튼 | <code>cafeteria__dining__soldout__submit</code> |
| fail | 제출한 내용이 처리되지 않음 | 제출 버튼을 눌렀지만 실패했을 때(서버 응답 기준) | <code>cafeteria__dining__soldout__submit</code> |
| exposure | 화면에 자동으로 보여짐 | 사용자가 누르지 않아도 화면 진입 시 A/B 안이 보일 때 | <code>cafeteria__dining__abtest__exposure</code> |

### 헷갈리기 쉬운 것

| 비교 | 구분 기준 |
| --- | --- |
| click vs select | 버튼을 누르는 것 자체가 목적이면 click, 여러 값 중 하나를 고르는 게 목적이면 select |
| submit vs success | submit은 사용자가 제출 버튼을 누른 것, success는 서버에서 실제로 처리된 것. 버튼을 눌러도 실패할 수 있으므로 둘을 섞지 않는다 |
| click vs exposure | click은 사용자가 누른 것, exposure는 자동으로 보인 것. exposure는 사용자 활동으로 세지 않는다 |
